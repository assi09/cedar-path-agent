# Cedar Path Tutoring: Agent-Powered Business Assistant

EECE 503P/798S Agentic Systems, C3 Assignment.

**🎥 Demo video:** [Watch on Google Drive](https://drive.google.com/file/d/14MM2O5D-Y-TMOt3XSSjzU2tKD9TuoBVc/view?usp=sharing)

A chatbot for **Cedar Path Tutoring**, a fictional tutoring and exam-prep center in Beirut (grades 7-12).
The agent, **Lina**, answers questions from the business documents, routes every message to the right
handling path, collects leads, logs feedback and unanswered questions through tool calls, checks its own
draft before replying, and runs in a Gradio UI.

## How it works

```
user message ─► Router ─► Agent (persona + instructions + business docs + tools) ─► Reflection ─► reply
                  │                          │
     general_question / lead_collection /    ├─ record_customer_interest(email, name, message)
     feedback (LLM call, keyword fallback)   └─ record_feedback(question)
```

| Component | Where | Notes |
|---|---|---|
| Persona | `PERSONA` | Who Lina is: tone and style |
| Instructions | `INSTRUCTIONS` | Guardrails: no invented prices, always ask for an email, log unknown questions |
| Router | `route()` | JSON classification by the LLM, with `heuristic_route()` keywords as a fallback |
| Route handling | `ROUTE_HANDLING` | Each intent adds its own guidance. Feedback forces a `record_feedback` call |
| Tools | `record_customer_interest`, `record_feedback` | Print to the console and append to `logs/*.jsonl`. Schemas use MCP style (`MCP_TOOLS`) |
| Memory | `run_agent()` | The chat history is sent to the model on every turn |
| Reflection (bonus) | `reflect()` | A reviewer model (`gpt-4.1-mini`) flags six specific rule violations, e.g. invented facts, false "I've recorded it" claims, guessed names, skipped answers. The code decides whether to revise and overrides flags it can check itself (which tools actually succeeded). The draft and revised reply go to `logs/reflections.jsonl` |
| Safety net | `run_agent()` | If reflection sees the reply admit "I don't know" but the model skipped `record_feedback`, the code logs the question itself. The trace marks these calls |
| UI | Gradio `ChatInterface` | Has an **Agent trace** panel showing the route, the tool calls and the reflection result |

## Run it

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # then put your OPENAI_API_KEY in .env
python app.py                 # or open business_agent.ipynb and run all cells
```

Uses `gpt-4o-mini` for the agent and router, and `gpt-4.1-mini` for the reflection reviewer. Override them with `MODEL=` and `REFLECTION_MODEL=` in `.env`. Setting `GEMINI_API_KEY` instead
runs the agent on Gemini through its OpenAI-compatible endpoint.

## Tool-calling eval

`python scripts/eval_tools.py 3` runs 28 cases 3 times each and checks that the expected tool succeeded. The cases cover:
unanswered questions -> `record_feedback`, feedback -> `record_feedback`, leads with contact details (including Arabic
and a friend's details) -> `record_customer_interest`, and leads missing details, an invalid email, answerable questions,
off-topic questions or a prompt injection -> no tool. Some cases also check the reply text: no name guessed from an
email, no fake price accepted, cheaper options actually named.
Latest result: **84/84 (100%)**. One grey-area case (German Abitur) accepts either outcome, since "we don't offer it" and "I don't have that information" are both reasonable.
